# ADR-0005 — The collection view is an uncommitted TSV rebuilt by every card-data operation; grep is the filter path

**Status:** Accepted (2026-09-14) · **Ticket:** [#3](https://github.com/mattiasthalen/deck-composer-v2/issues/3)

## Context

The composer, a Claude Code skill, reads one derived file listing every owned card (#1). Rule 3: files in git are the source of truth, and a local index may exist only as a regenerable derived cache. ADR-0002 made committed data files JSON with an integer schema. The view is a join of the collection and the catalog; both are committed and both change independently, the collection at every ingest and the catalog at every enrichment or refresh.

Estimated 2026-09-14: one line per owned card with name, quantity, colour identity, type, mana value, legality, Game Changer flag, rank, sets and oracle text is about 130 KB for 603 cards and fits one context window; the design target of ten times that does not. Requests can scope the pool by excluding binders and ManaBox decks (#1), which changes the quantity available per card.

## Decision

**The view is a TSV file, `data/collection_view.tsv`, gitignored, regenerated by every `cards` operation.** Two comment lines carry the collection hash, the catalog's refresh date and the scope; then a header row; then one line per owned card sorted by name. Under a scope the quantity is what remains after the excluded binders and decks, computed by the collection module, and a card with nothing left is not listed.

Rejected: committing the view. It goes stale between an ingest and the next rebuild, it would need an exception to the JSON-with-schema convention, and the ingest change report already gives the reviewable diff of what changed.

Rejected: a binders column so the composer can subtract excluded binders itself. That is per-card arithmetic in a language model; the scoped view gives it the number.

**The filter path is grep and awk over the TSV inside the session.** The format is designed for it: one record per line, fixed column order, tabs never appearing inside a value, newlines in oracle text replaced. Rejected: a `cards query` operation with filter flags. It re-implements grep over a file the project controls, a pass-through layer.

## Consequences

- The view can never disagree with the catalog for long: every catalog write rebuilds it, and the composer's first step in a session is `cards enrich`, which rebuilds it offline when nothing is missing.
- A fresh clone has no view until one `cards` operation runs; that operation needs no network when the committed catalog covers the committed collection.
- Past roughly five times today's size the composer stops reading the whole file and greps. Assumption A7 records the threshold.
- Scope by persisted table is not in the view yet; the table store's interview (#6) decides the subtraction list the view will accept.
- A second consumer wanting a different projection writes its own from the catalog and collection through their readers; the view stays the composer's.
